`data/music-player.js`, `data/videos-page.js` and `data/home-page.js` are runtime consumers, not authored editing targets. No automatic bespoke page conversion is proposed.

Music's current playback predicate is `available && file`. An unavailable track remains listed, with playback disabled. Availability therefore cannot serve as visibility. Existing IDs such as `air-force-t0ny` must retain their differing asset filenames. Catalogue order and curated playlist order are distinct. `ALL` follows catalogue order; `CUSTOM` reads browser-local selection, not an authored Website playlist. Preserve `krispykp_custom_track_ids_v1` and `krispykp_custom_playlist_name_v1`, import/export behavior and storage-denial fallback.

Music lyric output uses text content, including multiline text. Preserve Unicode, apostrophes and internal blank lines. The nine stored entries include an orphan that current configuration validation does not reject. Preparation must retain it without renaming it to a similar track or inventing a relationship. New dangling references must be refused; existing unused records must remain recoverable and explicitly reported.

Video category/tab order comes from source array order. The desktop exposes six category tabs before More; mobile uses a selector. Tab items retain playlist position order. Latest lists deduplicate video IDs and use dates. Videos uses `publishedAt`, which the generator sets from playlist-added date before video-published date; Home prefers `videoPublishedAt`. Preserve these different established semantics. Duplicate projections of one video across latest/category/tab lists are not duplicate authored identities. Video deep links use YouTube video ID; Music deep links use track ID. Neither implies autoplay authority.

The Video runtime can consume optional `note,tag,url`; these are not existing authored fields in the generator input. Do not advertise them as editable without a durable source and declared projection. External thumbnails and fixed YouTube embedding remain external dependencies, not imported Media Library assets.

Home's `HOME_FEATURE_CONFIG` is an inline runtime constant (empty forced IDs, track shuffle on, latest-video random selection off). It has no authored configuration source. Keep those controls locked initially; catalogue/snapshot edits still naturally affect Home. Layout, shared shell, tournament configuration and browser preferences remain outside this contract.

## Proposed minimum schemas and operations

Names below are proposed for the executable checkpoint, not files added by this preparation. A small versioned JSON authored source, for example `data/site-structured-content.json`, should carry new visibility and durable Video overrides. Existing authored JS remains compatible; generated runtime files remain deterministic outputs. Avoid a second parallel catalogue that silently replaces existing IDs.

| Model | Stable identity and proposed editable values | Ordering / boundaries |
|---|---|---|
| Track | Existing `id`; `name,artist,album,available`; separately declared visibility; existing audio reference; artwork through an explicit structured media usage capability. | Catalogue order is an exact permutation. No ID rename, file deletion, audio upload/transcoding or arbitrary URL/code entry. |
| Authored playlist | Existing `id`, `name`; ordered unique track IDs for curated playlists. | `ALL` and `CUSTOM` modes retain their meanings and IDs; browser custom selections stay local. New authored playlist creation needs the declared create operation, stable generated ID and collision refusal. |
| Lyrics | Existing track ID association; plain multiline `lyrics`, preserved stored `title` with an explanation that it currently does not render. | Add a lyric entry only for a known track; retain legacy orphan separately. No Markdown/HTML interpretation. No renaming or deleting existing orphan history. |
| Video category / sub-tab | Existing category and tab IDs; `title`, ordered sub-tabs, playlist source ID, category featured video selection. | Special `latest` identity/type cannot become an ordinary playlist category. Exact permutations preserve identities. Changing a playlist ID requires a separately validated import; never imply that a config change refreshed external metadata. |
| Video authored overlay | Key by `videoId`; optional title/note overrides, explicit visibility; category/tab curated membership only through declared operations. | Keep imported metadata and dates separate; absent override inherits snapshot, explicit empty note differs from absent. Featured ID must resolve in the projected eligible catalogue. |

A proposed envelope is `{schemaVersion:1,music:{trackOverrides:[],playlistOverrides:[],catalogueOrder:[]},videos:{overrides:[],categoryOrder:[],tabOrders:[]}}`. Omitted optional override means inherit; arrays carry stable IDs, not numeric source offsets. Final field names/defaults and allowed operations must be frozen with executable fixtures before Admin advertises them. A no-op envelope must reproduce baseline output and IDs. New source declarations must not be injected into existing B/D/page/media protocols without negotiation.

Visibility has two independent meanings: an editorial public hidden state, and an Admin private draft excluded from public export. Declare them separately. A public hidden track cannot leak via Home, playlist references, lyrics projection, search or direct-link lookup. A hidden video cannot remain in latest/featured/curated projections. Retain private source and history so unhide restores identity, order, references and text. Public filtering does not remove already-public baseline asset bytes; hiding a track is not audio redaction or access control. New private-only artwork must be omitted from public export before planning, following the media contract. Do not delete baseline assets or infer owner-private status from existing availability.

For initial executable limits, propose 500 tracks, 100 authored playlists, 500 members per playlist, 100 categories, 200 total tabs, 5,000 unique imported video IDs; labels up to 200 Unicode characters, lyrics/note up to 32,000 characters. Existing baseline exceeds none of these observed text limits (track name 39, artist 8, album 36; longest lyric 1,710). Validate serialized UTF-8 byte limits too, within the inherited 48 MiB request and snapshot limits. Bound arrays, recursion, total text and output bytes before parsing/projection. Final limits require maximum and just-over-limit fixtures; these numbers are proposals, not current guarantees.

Audio references resolve only to existing in-root canonical MP3 files; they are not subject to the still-image codec. Artwork initially supports the existing image reference unchanged. Any replacement must declare a structured track artwork usage edge and use media's sanitized PNG/JPEG/WebP assets with complete shared-use review. Current background-image rendering must be included in the adapter/validator; do not pretend the existing page image-node capability already covers it. External Video thumbnail replacement is deferred until such an explicit usage is required.

## Source preservation and deterministic projection

Never evaluate owner-provided JS with VM, eval, dynamic import or the external generator as the structured input parser. Existing validators execute trusted repository configuration; that is not a safe editable-source contract. The one-time inventory used reviewed baseline literal assignments in an isolated VM with a timeout and disabled code generation. It does not enable an owner-input parser.

The full adapter must recognize only the declared literal assignment/export grammar using a constrained parser, refuse executable expressions, duplicate keys/IDs, spreads, computed properties, getters and ambiguous syntax, and preserve original comments, ordering, unknown literal fields and untouched byte spans. Do not use whole-file JSON replacement that drops unknown fields, or regex field edits. Safe string serialization must escape backticks, interpolation tokens, quotes and controls; preserve semantic Unicode/newlines and refuse script injection. If the grammar cannot be preserved, show a read-only diagnostic rather than execute or rewrite it. The legacy orphan lyric is a preserved baseline exception with explicit provenance, not permission to create new dangling records.

Video overlay projection is a pure offline operation over the exact pinned snapshot plus authored source. Precedence: original imported value, then explicit supported authored override; retain the original import and unknown fields privately for recovery. Resolve stable references before filtering, apply public/draft filtering, then rebuild tabs/latest/featured from eligible membership. Preserve current positions/date policies and counts unless the declared version explicitly changes them. No invented timestamp, duration or remote availability. An empty or stale featured reference must produce a diagnostic or declared fallback, never a silent remap. Both no-op parity and every override's Home/Videos fanout need executable proof.

Future generator integration must reapply durable overlays after every refreshed import. A generated-file edit would disappear on the current scheduled rebuild; therefore it cannot be the authored interface. Until Website implements and validates that persistence path, Video mutation remains unavailable. Preparation does not alter or trigger the existing workflow.

## Refresh boundary

An offline preview rebuild is credential-free, bounded and explicit, but is not an external refresh. The existing YouTube generator is credentialed and writes source directly; Admin must not invoke it, read its environment/key, trigger the workflow or call it a credential-free refresh.

If a real external refresh is subsequently enabled, it requires a declared source adapter: explicit owner action; a public credential-free endpoint or owner-supplied import; fixed allowed hosts/protocols, response/time/page/item/byte limits, no arbitrary URL or redirects to local/private addresses, cancellation, reviewed provenance and candidate-only staging. Missing/private/deleted videos require a visible diff, not irreversible source deletion. An unavailable credential-free provider returns an honest unsupported diagnostic and retains the pinned snapshot. Do not add a scraper or speculative provider framework to bridge the current credential requirement. No external request was made by this preparation.
