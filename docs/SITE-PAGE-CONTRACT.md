# Website page foundation contract — E1

The Website owns static page rendering, shared shell, route metadata/navigation and bounded body composition. Admin authors declarative private drafts and runs fixed trusted Website tools. This contract is separate from the approved B content and D1 About layout contracts, which retain their hashes/schema/semantics. A capability read is not a validation receipt or integration authority.

## Sources and defaults

Registry data/site-pages.json is siteId krispykp/schemaVersion1/adapter static-pages-v1 with immutable existing route descriptors and bounded pages[]. Contract data/site-pages-contract.json declares protocol1 capabilities pages.compose.v1/pages.routes.v1/pages.shell.v1/snapshot.validation.v1. Paths, limits, supported templates/components and adapters are checked against trusted code; manifests never choose commands.

Seven existing bodies, metadata, style/runtime order, B/D attributes, Privacy footer/no social row/page-contact class, and Tournaments background order remain intact. Central Website partials tools/pages/partials/{header,footer,footer-privacy,background,background-tournaments}.html describe only trusted shell source. Primary/footer links derive from the registry, with current route markers. No default HTML changes or new public route; empty managed stylesheet is not loaded by existing pages. A private new navigation proposal binds the generated stylesheet on existing routes only to wrap the new managed link labels; removing all such proposals removes that binding. Existing navigation styles and labels stay unchanged.

Existing HTML remains authoritative for bespoke main content/metadata/runtime. On projection, parsed shell segments are compared with central definitions; equivalent whitespace is retained. Changed shell segments replace only header/footer/background. New pages use the same current shell plus shared site.css/command-deck.css/Radar/site-ui assets and derived metadata, not frozen Admin copies. Website maintenance tools/pages/build.mjs --root <root> --check|--write deterministically regenerates shell and managed outputs. Admin must use the immutable planner instead. Fixed Website partial changes are trusted source work, not user-authored HTML or supported Admin operations.

## Routes, metadata and composition

Exact page/component schemas and CLI examples are in SITE-PAGE-CONSUMER.md; tools/pages/fixtures.mjs exports reproducible definitions. New route /<slug>/ always maps to <slug>/index.html. Slugs are canonical lower-case ASCII words <=64 characters, letter-first, separated by single hyphens. Existing route descriptors cannot change. Root case aliases, occupied paths, reserved infrastructure/asset/tooling/data names, Windows devices, traversal/encoding and linked paths are refused. IDs page.<slug> and unique component IDs determine scoped render identities; arbitrary output paths are not accepted.

Blank retains a visible page-name H1 and no decorative hero; hero must be null. Standard supports optional bounded hero title/summary. Both include proper derived canonical/Open Graph/Twitter metadata, fixed site origin and favicon references. Existing metadata/JSON-LD are untouched. Sitemap contains every registered route. Navigation visibility controls candidate links only; hidden links are not confidentiality. The initial state contains no new page or navigation proposal.

Initial library: heading (H2/H3 with hierarchy), plain text, route/HTTPS CTA, existing PNG image reference with required alt/intrinsic dimensions, panel and bounded intrinsic grid. At most20 managed pages,80 nodes/page,depth5 and20 children/container. No raw HTML/CSS/commands/absolute coordinates, scripts/media players/forms, arbitrary paths or new uploads. Page grids use wide>=981/max3, medium701–980/max2 and compact<=700/max1, wider-profile inheritance/capping and actual DOM order. Null profile values inherit. Panel/grid nesting and unique IDs are checked; render parity verifies exact generated document, stylesheet and ID map. Richer media/structured components remain later contracts; B upload semantics are unchanged.

## Projection and preservation

Optional request.pageOperations contains createPage or setPage, exact id/kind/expectedOld/value, <=20 distinct page IDs. Create requires null expectedOld and absent/nonoccupied derived route; set requires complete baseline page definition and unchanged ID/slug. Rename/delete is not supported. A whole-page replacement is declarative net composition, not arbitrary source replacement. Collapse journal history to baseline-to-final operations, preserving stable IDs for unchanged nodes; undo/reset to the baseline gives zero source outputs.

Existing B operations and D1 layoutOperations may coexist. The planner runs content, About layout, then page/nav projection against one immutable baseline, preserving independent same-file edits. It requires current baseline/contract/layout/pages/shell digests and exact baseline source hashes. Page operations cover registry, generated page CSS, sitemap, all seven existing HTML files and all baseline-managed HTML in expectedFiles, plus B/D touched sources. Plan returns exact actual sorted outputs; materialise requires identical allowedOutputs. No-op outputs are empty; unrelated data/media/unknown bytes are retained.

Snapshot inventory discovers only canonical paths from a validated fixed registry. New routes permit only <slug>/index.html; other files/nested directories in those route folders remain private/unsupported. Full snapshot/candidate checks retain case/symlink/credential/private-file containment. Capture fresh identities and source hashes from actual checkout bytes; Git LF/CRLF variants can legitimately differ from historical raw hashes. Neither historical digests nor a source manifest establish trust.

Validate replays the deterministic plan against baseline, verifies exact changed paths and every generated byte, performs full source and browser gates including registry-aware new routes, and rehashes baseline/candidate after validation. The whitespace gate compares new files against an empty private file rather than a nonexistent baseline path; real whitespace faults still fail. PASS receipts bind baseline/request/consumer/content/layout/pages/shell/candidate hashes and output scopes; process completion alone is insufficient. Integration/remotes/publication are explicitly NOT_RUN in private receipts and checked separately for task delivery.

## Actual preview and lifecycle

Fixed pages CLI can prepare a private selection bridge for a validated managed page only. It checks actual candidate inventory digest and derives routes/attribute/IDs/tag/parent/order from Website mappings. Installation refuses wrong origin/route or mismatched/duplicate live render maps; runtime drift invalidates selection. Existing About uses its original D1 scope. Edit/inspect/interaction, CSS-pixel geometry/revision, keyboard/Escape, scroll/resize/visual viewport, reattach/navigation/pagehide/detach use the existing private protocol. No editor script/markup is loaded or exported by public pages.

E2 must also validate current host receipt, origin/session/document/candidate identity/revision and exact live mapping before inspector/actions. Geometry is ephemeral and never persisted as coordinates. New edits/history/rebase/navigation/refresh invalidate old proof. Native WPF/WebView2 drag/focus/zoom/DPI/physical input and assistive-technology quality remain Admin/manual checks, not browser claims.

## Delivery gates

Final E1 delivery supplies source/current-route acceptance, private mixed new-route acceptance, refusal/preservation/default-parity/global propagation/threshold/keyboard/selection tests, rendered whole-site review, exact trusted code LF/CRLF forms checked against delivered Git revision, and exact task commit/remote/clean state. Owner finished-product testing/acceptance and main integration/deployment remain separate. This interface does not authorise Admin to push or publish the Website.
